# Frontend API contract
All endpoints under /api; local single-user app. Values serialized strings for amounts.
GET /api/health => {status,version,openrouter_configured,openrouter_enabled,model,ocr_available}
GET /api/dashboard => {total_runs,approved,needs_review,rejected,failed,processing,total_approved_by_currency:{USD:'...'},recent_runs:[Run]}
GET /api/runs => {runs:[Run]} optional ?status=approved&search=term
GET /api/runs/{id} => Run
GET /api/runs/{id}/deletion-preview => {run_ids:[string],count,filenames:[string],approved_count,can_delete,reason,fingerprint}. Read-only confirmation for the complete original-upload family, including batch rows and correction versions. Independent duplicate uploads are not included. Queued, processing, or still-active batch uploads cannot be deleted.
DELETE /api/runs/{id} JSON {expected_fingerprint:string} => {deleted_run_ids:[string],count,cleanup_pending:boolean}. Permanently removes the confirmed upload family and source files, releases its approved PO amount/quantity commitments, and retains a minimal deletion audit without invoice content. The fingerprint is required and checked atomically; changed/active previews return409, missing IDs404. Source files are staged before the database transaction and restored on rollback. If final file removal fails after commit, cleanup_pending is true; those files are inaccessible through the API and cleanup retries at startup. PO/vendor records and unrelated uploads remain. Retained duplicate runs keep their historical decision and duplicate_of ID with result.duplicate_source_deleted=true, so the UI hides navigation to the deleted source.
GET /api/runs/{id}/calculations => {run_id,invoice_fingerprint,rules,rules_basis,superseded}. Current deterministic result, per-product totals and explicit defaults; older rule versions receive a labeled current preview without changing the saved decision. AI calculation generation has been removed.
POST /api/runs/upload multipart `files` (multiple) => {runs:[Run]}; limit 10 files, 10MB each. Each file initially one parent run, batch CSV/JSON may spawn children.
POST /api/runs/text JSON {text,filename?:'invoice.txt'} => {runs:[Run]}
POST /api/runs/structured JSON {invoice:{...}} => {runs:[Run]}
POST /api/demo/{scenario} => {runs:[Run]}; scenario happy_path|duplicate|split_overage|ambiguous_po|missing_fields. Duplicate creates pair; split_overage creates pair. Each click uses unique invoice ids to avoid prior demo interference; demo uses own vendors/POs.
GET /api/demo => {scenarios:[{id,title,description}]}
POST /api/runs/{id}/review JSON {action:'approve'|'reject',reviewer,comment,po_number?:string} => Run; 409 if hard checks prevent approval. Requires comment/reviewer. Re-evaluates live state. Can select PO for ambiguity.
POST /api/runs/{id}/correct JSON {invoice:{...},reviewer,comment,expected_invoice_fingerprint?:string} => {runs:[Run]}; supersedes an unapproved completed run and creates an audited, newly evaluated correction. Approved runs must first be rejected. Exactly one invoice is accepted. When supplied, the fingerprint is checked atomically before superseding; a stale fingerprint returns409. Both runs retain normalized business-field changes as reviews[].changes:[{field,before,after}].
GET /api/runs/{id}/review-context => {run_id,updated_at,invoice,invoice_fingerprint,comparisons,evidence,raw_text,warnings,issues,editable,read_only_reason}. Read-only; completed runs only. Comparisons contain {field,local_value,ai_value,local_evidence,ai_evidence,disagrees,selected_source,origin:'saved'|'reconstructed'}. New OpenRouter extractions retain candidates; legacy reconstruction uses stored text, labels its origin, and never replaces saved invoice data. No model call.
POST /api/runs/{id}/correction-preview JSON {invoice:{...},expected_invoice_fingerprint?:string} => {run_id,invoice,result,issues,changes,preview_only:true,message}. Reuses structured normalization and current policy with the prospective replacement source hash, excluding the current run from duplicate/capacity checks. No writes, supersession, approval or capacity reservation. Preview assumes the submitted values are source-verified; actual correction rechecks current state. Requires an unsuperseded, unapproved completed run. Issues are {fields:{'line_items.0.quantity':[Check],...},general:[Check]}; field/row paths use zero-based indexes. Amounts remain decimal strings. Stale fingerprints return409.
GET /api/runs/{id}/source => original input attachment; batch rows resolve to their original parent source.
GET /api/runs/{id}/documents => read-only document context: {run_id,status,matched_po,matched_vendor,match_message,invoice_source,invoice_source_message,processed_input,po_source,po_source_message}. PO/vendor values are the snapshots stored with the run. Sources have {filename,source_id,source_role,preview_url,download_url,source_sha256}; unavailable sources are null with an explanation. Corrected runs' invoice_source follows correction lineage to the original upload; processed_input identifies only the current corrected JSON. PO files are linked only through that snapshot's confirmed upload, never a later registry revision.
GET /api/runs/{id}/source/preview => {filename,kind:'pdf'|'image'|'text'|'unsupported',page_count,preview_page_count,text,truncated,message,page_url,download_url}. This previews the same input as that ID's source download; use the document context to resolve the original upload for corrections. Batch children resolve to the parent file.
GET /api/runs/{id}/source/preview/page?page=0 => PNG page, zero-based. Max20 preview pages, max1600px edge, bounded source size/dimensions; original downloads unchanged. Text content is returned as text in JSON, never HTML.
GET /api/procurement/uploads/{id}/source/preview and /source/preview/page?page=0 => same preview contract for retained PO sources. Missing files/pages return404; oversized sources413; corrupt/encrypted or excessive-dimension documents422. UI retains original download when preview fails.
GET /api/runs/{id}/export?format=json|csv|html => download
GET /api/runs/export?format=json|csv => all results download
GET /api/procurement => {vendors:[Vendor],purchase_orders:[PO],policy:Policy}
GET /api/procurement/purchase-orders/{po_number}/documents => {po_number,po_source,po_source_message,record_source}; read-only original-upload context for the current registered PO. URL-encode the PO number; embedded slashes are supported. Unknown POs return404. No draft, validation or approval is created.
GET /api/procurement/uploads/{id}/documents => {upload_id,po_source,po_source_message,record_source}; same context for an upload/review draft. Unknown uploads return404. Sources use the document-context shape above. Registered-record JSON snapshots are returned separately as record_source; po_source always identifies an actual uploaded document. Server-created review drafts retain review_of_po and prior_po_upload_id, and each prior upload must be confirmed for the same PO. Older confirmed reviews can recover this link from their recorded audit event. Missing or unverifiable sources return null with an explanation; current registry records are never substituted into historical invoice sources.
POST /api/procurement/import JSON {vendors?:[Vendor],purchase_orders?:[PO]} => same object; atomic validate/upsert. Replacing committed amount forbidden (ledger-derived).
The import endpoint is legacy compatibility only: new vendors are pending even if supplied as approved; existing approval changes and approved/rejected vendor identity changes are refused. Uploaded PO validation metadata is ignored, and changed/unreviewed POs remain unverified. Use the [PO upload and independent vendor-review contract](po-upload-contract.md) for the supported review workflow, templates, required fields, draft revisions and confirmation routes.
PUT /api/policy JSON {tolerance_percent:'2',tolerance_absolute:'5',min_confidence:0.85} => policy

Run: {id,filename,status:'queued'|'processing'|'completed'|'failed',decision:null|'approved'|'needs_review'|'rejected',created_at,updated_at,invoice:null|Invoice,events:[{stage:'ingest'|'extract'|'validate'|'match'|'decide'|'output'|'review',status:'running'|'completed'|'failed',message,at}],result:null|{decision,summary,checks:[{code,label,status:'pass'|'warn'|'fail',message,blocking}],matched_po,matched_vendor,duplicate_of},extraction:null|{method,evidence,warnings,raw_text,field_comparisons?},error:null|string,reviews:[{action,reviewer,comment,at,changes?:[{field,before,after}]}],source_sha256,parent_id?,correction_of?,superseded_by?,policy_snapshot?,original_decision?}
Invoice: {invoice_number,vendor_name,vendor_id,po_number,invoice_date,due_date,currency,subtotal,tax,total,line_items:[{description,quantity,unit_price,amount}],extraction_confidence}
Vendor: {id,name,aliases:[],approved:boolean,approval_status:'approved'|'pending'|'rejected',approval_history?:[]}
PO: {po_number,vendor_id,vendor_name,po_date,currency,subtotal,tax,total,committed,approval_status:'approved'|'pending'|'rejected',status:'open'|'closed',description?,line_items:[],validation_status:'validated'|'unverified',eligibility_status:'eligible'|'pending_vendor'|'ineligible'|'unverified',validation_issues:[]}. Legacy rows may lack required fields and remain unverified until reviewed.
Seed vendors: vendor-acme / Acme Cloud Services; vendor-northstar / Northstar Office Supply. POs PO-2026-001 Acme USD 12000; PO-2026-002 Northstar USD 5000; PO-2026-003 Northstar USD 7500.
Structured sample: {invoice_number:'INV-1001',vendor_name:'Acme Cloud Services',po_number:'PO-2026-001',invoice_date:'2026-11-09',currency:'USD',subtotal:'1000',tax:'100',total:'1100',line_items:[{description:'Cloud platform subscription',quantity:'1',unit_price:'1000',amount:'1000'}]}
The UI should poll actual run objects every ~800ms while pending; no fabricated stage progress. Errors {detail:string}. Links exports ordinary relative downloads. API served same-origin when production build available; Vite proxies /api to localhost:8000.
